# 파라미터 포맷

아트록스 맵 에디터의 파라미터는 유닛 능력치, 업그레이드, 특수능력 세 묶음이다. 맵 파일의 LHA 압축을 푼 MAPDATA([spm-format.ko.md](spm-format.ko.md)) 안에 플레이어 여덟 명분이 차례로 들어 있다.

정수는 전부 리틀 엔디언이고 문자열은 CP949 다.


## 위치

파라미터 앞에 오는 맵 데이터의 구조는 아직 다 확인하지 못했다. 그래서 Parameter Packer 는 고정 오프셋 대신 플레이어 1 의 첫 유닛인 엔지니어의 이름 문자열을 찾아, 그 8바이트 앞을 시작으로 삼는다. 이름 앞에 4바이트 필드 두 개(기본설정, 기본이름)가 있기 때문이다.

```gml
para_pos = file_bin_position(data_file)-string_length(find_string)-8
```

맵 에디터로 저장한 한 맵에서는 1,473,311바이트 MAPDATA 의 `0x1297DC` 에서 시작해 `0x15DF8C` 에서 끝났다.


## 전체 구조

```
플레이어 1 유닛 능력치    0xC2 × 123 = 0x5D36바이트
플레이어 1 업그레이드     0x20 × 58  = 0x740바이트
플레이어 1 특수능력       0x24 × 32  = 0x480바이트
플레이어 2 유닛 능력치
...
플레이어 8 특수능력
```

플레이어 하나가 `0x68F6`(26,870)바이트, 여덟 명이 `0x347B0`바이트다. 플레이어 사이에 빈자리는 없다.


## 유닛 능력치 (0xC2바이트)

| 오프셋 | 크기 | 항목 | 형식 |
|---|---|---|---|
| `+0x00` | 4 | 기본설정 | 정수 |
| `+0x04` | 4 | 기본이름 | 정수 |
| `+0x08` | 100 | 이름 | 문자열, 남는 자리는 0 |
| `+0x6C` | 4 | 체력 | 정수 |
| `+0x70` | 4 | 장갑 | 정수 |
| `+0x74` | 4 | 방어력 | 정수 |
| `+0x78` | 2 | 시간 | 정수 |
| `+0x7A` | 2 | 뮤온 | 정수 |
| `+0x7C` | 2 | 쿼크 | 정수 |
| `+0x7E` | 20 | 대지공격 | 문자열 (`일반`, `충격`, `관통`, `폭발`) |
| `+0x92` | 4 | 대지기본 | 정수 |
| `+0x96` | 4 | 대지추가 | 정수 |
| `+0x9A` | 4 | 대지히트 | 정수 |
| `+0x9E` | 20 | 대공공격 | 문자열 |
| `+0xB2` | 4 | 대공기본 | 정수 |
| `+0xB6` | 4 | 대공추가 | 정수 |
| `+0xBA` | 4 | 대공히트 | 정수 |
| `+0xBE` | 4 | 맵에등장 | 정수 |

기본설정은 1 이면 아트록스 기본 능력치를, 0 이면 맵에 적힌 값을 쓴다. 기본이름은 같은 식으로 이름을 정한다. 맵에등장은 1 이면 그 유닛이 나오고 0 이면 나오지 않는다.

위 맵의 플레이어 1 첫 유닛은 이렇다.

| 항목 | 값 |
|---|---|
| 기본설정 / 기본이름 | 1 / 1 |
| 이름 | 엔지니어 |
| 체력 / 장갑 / 방어력 | 50 / 50 / 0 |
| 시간 / 뮤온 / 쿼크 | 20 / 50 / 0 |
| 대지공격 / 기본 / 추가 / 히트 | 충격 / 0 / 0 / 1 |
| 대공공격 / 기본 / 추가 / 히트 | 충격 / 7 / 0 / 1 |
| 맵에등장 | 1 |


## 업그레이드 (0x20바이트)

4바이트 정수 여덟 개다.

| 오프셋 | 항목 |
|---|---|
| `+0x00` | 기본설정대로 한다 (0 / 1) |
| `+0x04` | 시간 기본 |
| `+0x08` | 시간 추가 |
| `+0x0C` | 뮤온 기본 |
| `+0x10` | 뮤온 추가 |
| `+0x14` | 쿼크 기본 |
| `+0x18` | 쿼크 추가 |
| `+0x1C` | 개발 가능하다 (0 / 1) |


## 특수능력 (0x24바이트)

4바이트 값 아홉 개이고 그중 일곱째와 여덟째는 소수를 쓰는 32비트 float 다.

| 오프셋 | 항목 | 형식 |
|---|---|---|
| `+0x00` | 기본설정대로 한다 (0 / 1) | 정수 |
| `+0x04` | 에너지 소모 | 정수 |
| `+0x08` | 효과 / 데미지 / 속도 | 정수 |
| `+0x0C` | 증가치 | 정수 |
| `+0x10` | 사정거리 | 정수 |
| `+0x14` | 효과 범위 | 정수 |
| `+0x18` | 유효 시간 | float |
| `+0x1C` | 단계 적용 시간 | float |
| `+0x20` | 사용한다 (0 / 1) | 정수 |

위 맵에서 유효 시간 자리에는 `0x41F00000`(30.0), `0x3F333333`(0.7) 같은 값이, 단계 적용 시간 자리에는 `0x3F000000`(0.5), `0x3E99999A`(0.3) 같은 값이 들어 있다.


## Parameter Packer 의 텍스트 형식

Parameter Packer 는 플레이어마다 `<MAPDATA 이름>_parameter1.txt` 부터 `_parameter8.txt` 까지 하나씩 쓴다. 한 파일에는 아래 순서로 적힌다.

1. 유닛 123개. 유닛마다 위 표의 순서대로 `항목이름    값` 꼴의 줄 18개, 그리고 빈 줄 하나.
2. 업그레이드 58줄. 줄마다 값 여덟 개를 공백 네 칸으로 띄워 쓴다.
3. 빈 줄 하나.
4. 특수능력 32줄. 줄마다 값 아홉 개.

```
기본설정    1
기본이름    1
이름        엔지니어
체력        50
...
맵에등장    1

1    60    0    100    0    100    0    1
...
```

모든 4바이트 값을 정수로 읽고 쓰므로 특수능력의 float 두 칸은 비트 그대로의 정수로 나온다. 30.0 은 `1106247680`, 0.7 은 `1060320051` 이다. 고칠 때도 float 를 같은 방식으로 정수로 바꿔 적어야 한다.

다시 넣을 때는 줄마다 첫 공백 뒤의 앞쪽 공백을 지운 나머지를 값으로 읽는다. 그래서 항목 이름에는 공백이 없어야 하고 이름 값 안의 공백은 그대로 남는다. 업그레이드와 특수능력 줄은 공백 네 칸을 한 칸으로 바꾼 뒤 한 칸 단위로 자른다.
